# CodeSprite 开发文档

> 状态规则：只有进入正式工程、核心交互可用且通过构建或桌面回归的功能才标记为 `[x]`。

## 1. 产品边界

CodeSprite 是 Windows 程序员桌面小工具箱。主入口是透明玻璃水球，水位映射 CPU 或内存；点击水球展开卫星入口，每个功能在独立、可拖动、可缩放的原生透明窗口中运行，不依赖一张覆盖桌面的透明大页面。

产品原则：打开快、操作短、默认安静、本地优先。未来的云同步、Team 命名记忆和 AI 宠物应通过现有接口扩展，不应侵入工具业务代码。

## 2. 架构

```text
src/
├─ ai/                 AI Provider 适配层
├─ config/             工具注册表、窗口规格和默认配置
├─ core/               领域类型，不依赖 UI 与 Tauri
├─ platform/           Tauri 原生调用边界
├─ storage/            版本化本地数据仓库
├─ theme/              主题清单、语义令牌和渲染器类型
├─ todo/               Markdown 文档解析、序列化与报告生成
├─ naming.ts           可测试的本地命名降级引擎
├─ main.ts             窗口路由与功能控制器
└─ styles.css          组件结构样式，颜色/字体/球体参数读取主题令牌

src-tauri/src/lib.rs    系统指标、窗口、凭据、剪贴板、进程和本地文件能力
```

依赖方向：功能控制器依赖领域类型与接口；存储、AI、主题、窗口能力互不直接依赖。新增工具应先加入 `TOOL_REGISTRY`，再实现对应视图和控制器。窗口尺寸由注册表传入 Rust，不在原生层逐工具写死。

## 3. 主题系统

主题是 `ThemeManifest`：

- `id` / `name`：稳定标识与展示名称。
- `renderer`：当前为 `water-orb`，已预留 `pet`。
- `tokens`：字体、主辅色、表面、边框、阴影、球尺寸、水色、圆角等语义变量。

当前包含“深海玻璃”和“紫雾星云”。切换主题只更新 CSS 变量；工具逻辑不包含主题判断。以后实现桌面宠物时，应新增 `pet` 渲染器组件和主题资源包，不改剪贴板、待办或 AI Provider。

## 4. 数据与安全

- 业务数据统一由 `AppRepository` 读写，不允许功能自行创建 `localStorage` 键。
- 桌面版数据位于系统应用数据目录的 `codesprite-data-v1.json`，包含 `schemaVersion`，写入前校验 JSON，并保留 `.bak` 备份。
- 各 WebView 通过 `app-data-changed` 原生事件同步，不共享易失的内存状态。
- 不同 WebView 只提交发生变化的顶级数据分区，Rust 在全局互斥锁内读取最新文件并合并，避免剪贴板后台写入覆盖主题或待办设置。
- MiMo API Key 使用 Windows Credential Manager 保存，不写入源码、JSON、日志或 Git。
- 自动剪贴板历史会跳过私钥和明显的 API Key/password 文本；目前普通剪贴板记录仍是本地明文，后续加密数据库完成前不应宣称可安全收藏密码。
- 云同步与 Team 模式未来应实现新的 Repository/Sync Adapter，领域模型保持不变。

## 5. 功能清单

### 5.1 桌面外壳

- [x] Tauri 2 透明无边框主球窗口。
- [x] 原型休眠态：48px 水球；悬浮向左展开内存、CPU、待办数量状态条，水球位置保持不动。
- [x] 真实 CPU、内存与容量数据。
- [x] 水位可配置映射 CPU 或内存。
- [x] 拖动主球，快速移动时产生水体惯性动画。
- [x] 点击展开已启用的卫星工具入口，再点中心或空白处收起。
- [x] 卫星入口分别使用 `72×72` 原生透明窗口，不再依赖承载全部入口的矩形 WebView。
- [x] 功能球显隐可配置并本地持久化；轨道参数集中配置，数量变化后自动均匀重排。
- [x] Windows 下绕过普通窗口最小宽度限制，透明命中区域与功能球配置尺寸一致。
- [x] 展开时隐藏系统状态提示，悬浮提示不被窗口裁切。
- [x] 工具使用独立原生窗口，可拖动、缩放和关闭。
- [x] 置顶为用户设置，默认关闭，并同步应用到所有窗口。
- [x] 常驻待办为独立小窗，默认不显示。
- [x] 打开任意工具窗口时暂时隐藏常驻待办，关闭最后一个工具后恢复，避免透明矩形窗口拦截点击。
- [x] 系统托盘：关闭主窗口后驻留；左键恢复水球；右键快速打开各功能或彻底退出。
- [x] 多显示器边缘检测；水球靠近边框后缩为原生窄窗口和发光细线，点击恢复。
- [ ] 全局快捷键和开机自启。
- [ ] 水球窗口位置与吸边状态持久化。

## 6. 验证

日常提交前运行：

```powershell
npm run check
cargo test --manifest-path src-tauri\Cargo.toml
```

本轮桌面规格：主窗休眠态 `120×120`，状态条态 `360×120`，缩放以距右侧 60px 的水球中心为锚点；功能球为 `72×72` 独立透明窗口并按统一轨道动态排布；命名 `760×210`；剪贴板 `560×440`；待办 `720×620`；工作区 `620×480`；端口进程 `520×390`；设置 `620×560`；常驻待办 `300×220`。窗口创建命令必须保持异步，避免阻塞 Tauri IPC；卫星窗口和常驻待办必须包含在 capability 的窗口范围内。

发布与更新服务器配置见 [`docs/UPDATES.md`](./UPDATES.md)。

MiMo 联网测试必须由用户在设置页输入一枚有效且未泄露的 Key。泄露过的 Key 不进入测试、源码或默认配置。

MiMo 凭据路由：`sk-` 使用 `https://api.xiaomimimo.com/v1`；`tp-` 使用 `https://token-plan-cn.xiaomimimo.com/v1`。两类 Key 与计费体系不互通。程序只在当前地址属于 MiMo 官方地址时自动纠正路由，自定义代理地址不会被覆盖。
